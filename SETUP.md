# setting this up

This repo is your GitHub profile README (`shreyaxdalvi/shreyaxdalvi`). Everything
in it -- the ASCII portrait, the section headings, the stats graphics -- is
generated by files already in this repo. Nothing is fetched from a
third-party service at view time.

## 1. push it

```bash
cd shreyaxdalvi
git init
git add .
git commit -m "init: self-generating profile"
git branch -M main
git remote add origin https://github.com/shreyaxdalvi/shreyaxdalvi.git
git push -u origin main
```

The repo name has to match your username exactly, or GitHub won't treat it
as a profile README.

## 2. run the stats workflow once

`assets/stats/` is empty until the nightly Action runs, so the four stats
images (`hero.svg`, `streak.svg`, `langs.svg`, `year.svg`) will 404 until then.
Trigger it manually the first time instead of waiting for the 05:17 UTC cron:

**Actions tab -> "refresh stats" -> Run workflow.**

It uses the built-in `GITHUB_TOKEN` -- no secrets to add.

## 3. force the profile page to pick it up

A newly created profile README is sometimes cached. If it doesn't show up
on `github.com/shreyaxdalvi`, open `README.md` in the GitHub web UI and hit
"Edit" then "Commit" without changing anything -- that forces a refresh.

## 4. two things the API can't do

- **Pinned repositories** and **bio** have no GraphQL mutation and no REST
  scope your CLI token will have. Set both manually in the profile UI.

## regenerating the portrait with a different photo

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
python3 scripts/generate_portrait.py path/to/new_photo.png assets/portrait.svg \
    --cols 90 --font assets/fonts/ramp.woff2
```

Crop tight (chin to just above the hairline), side-lit at roughly 45 degrees,
1200px+ resolution, plain background. See the pipeline notes in
`scripts/generate_portrait.py` for why each of those matters -- the short
version is that ASCII draws with shadow, not detail, so a flatly-lit,
low-res photo renders as a featureless blob.

If the background removal eats your hair (it will, on `u2net`, against a
dark or busy background), that's why the script uses `u2net_human_seg`
instead -- keep that model if you swap photos.

## regenerating a heading

```bash
python3 scripts/generate_heading.py "new heading text" assets/headings/new_heading.svg \
    --ttf assets/fonts/JetBrainsMono-Regular.ttf
```

Then reference `./assets/headings/new_heading.svg` from `README.md`.

## a note on the README's line breaks

GitHub's renderer turns a single newline inside a paragraph into `<br>`
automatically (unlike strict CommonMark). `README.md` here relies on that --
plain newlines at natural wrap points, no manual `<br>` tags -- so if you
add prose, wrap it with plain newlines rather than adding your own `<br>`,
or you'll get doubled line breaks.
